═══ 三、三段核心机制 ═══
  · sing1(vols)：vols 与它自己的 shift(1..5) 一起 merge_many（inner），
    按 code 分组跑 rp.ols(X=[vols_lag1..vols_lag5], y=vols) 得 6 个 beta + r2；
    再按同一分组 predict 出每只股票自己的 r2s（用别人的回归系数预测自己的波动率），
    然后 r2st = r2s.T、r2trans = r2s - r2st、r2s_ab = r2s - r2_pri、r2st_ab = r2st - r2_pri，
    再算 corr_in_out（r2s 与 r2st 的逐元素相关，用 rp.dataframe_corrwith）、
    三个 uprate（count/size）、以及 mean/std/skew/kurt/median/max/min 一大串。
    38 个量里 corr_in_out 用 rp.dataframe_corrwith（两个方阵按 code 交集对齐后逐元素相关），
    r2s = r2s.where(r2s >= 0, nan)。
  · sing2(rets)：rets 与 shift(1..15) 一起 merge_many，同样的分组 OLS（16 个 lag），
    之后与 sing1 的 38 个量完全同构。
  · sing3(x, y)：x 与 y 各自的 shift(1..5) 一起 merge_many，
    同一分组里做两个回归（x 对 y 的 lag、y 对 x 的 lag），再同构那 38 个量。
  ⇒ sing1/sing2/sing3 的区别只在「输入几个 lag、用哪些列」，38 个量的算法是**同一段代码**，
    建议在 Rust 里抽成一个公共函数。

═══ 四、必须逐字复刻的第三方实现（这是这个系列的主要风险） ═══
  · dwo.merge_many 的语义：`df.stack().reset_index()` 之后 outer join（本例 how='inner'）。
    stack 默认 dropna=True，所以**每个 NaN 格子不生成行**，行集合是各帧的并集/交集；
    于是 shift(k) 是「沿时间往前数第 k 个**存在**的行」，不是往前第 k 分钟。
    这套语义在 src/okay_database/hm028.rs 的文件头第二节里已经写得很细，直接照那条路走。
  · rp.ols：返回 [b0, b1, ..., bk, r2]，源码 src/statistics/mod.rs，
    正规方程 + solve_linear_system3（无主元 LU），r2 = 1 - ss_res/ss_tot 都是朴素顺序求和。
    worker 链路里**不能**直接调 #[pyfunction]，要在自己文件里抄一份纯 Rust。
  · rp.dataframe_corrwith：两个方阵、按 code 交集对齐后逐元素相关，
    源码在 src/pandas_corrwith.rs（自己确认一下是不是 Welford 还是两遍法）。
  · pandas 的 .kurt()：无偏 G2（bias 修正），和 skew 一样要点开
    pandas/core/nanops.py 的 nankurt 逐字抄；.skew() 见 my hm000.rs 里的 nanskew。
  · .mean()/.std()（axis=0）都是逐列；多列 C 顺序数组上 axis=0 的求和在 numpy 里是
    **顺序累加**（实测），std 是 ddof=1 的两遍法。
  · names_save 里用了 `list(set(...))`（names_save_unfold），顺序不确定；
    它只用于落盘、不影响 names()，但写 Python 侧文件时不要把它的顺序当成有意义的。
