═══ 三、列变换（照抄旧代码的顺序）═══
  volume_66 = volume*(flag==66)，volume_83 = volume*(flag==83)  ← 都用**变换前**的 volume
  exchtime_float = exchtime 的纳秒 float
  price = (price - price.shift(1)).abs()        ← 第 0 行是 NaN
  price = price.cumsum()/price.sum()            ← pandas cumsum 跳过 NaN：第 0 行留 NaN，之后正常累加
  volume = volume.cumsum()/volume.sum()
  volume_66 = volume_66.cumsum()/volume_66.sum()
  volume_83 = volume_83.cumsum()/volume_83.sum()
  exchtime_float = (exchtime_float - min)/(max - min)
  注意 price 与 volume 的 cumsum 顺序：先 price 的 absdiff，再 price 的 cumsum，
  再 volume 的 cumsum —— 不要互相污染。

═══ 五、三个必须自己写纯 Rust 的零件 ═══
  1) rp.segment_and_correlate（src/sequence/mod.rs:1623，是 #[pyfunction]，worker 链路上不能调）
     逐行照抄即可：按 a[i]>b[i] 分段，段长 >= min_length 才留；
     每段算 Pearson（两遍算法，均值→协方差），分母恰好 == 0.0 才丢；a>b 的段进第一个列表。
     注意：段里含 NaN 时 Pearson 返回的是 **NaN 而不是被丢掉**（分母是 NaN，NaN==0.0 为假），
     所以列表里会带 NaN，后面的统计量必须按 pandas 的 skipna 处理。
  2) rp.dtw_distance（src/time_series/mod.rs:97，同样是 #[pyfunction]）
     经典 DP，矩阵 (n+1)×(m+1) 全填 INFINITY，[0][0]=0，
     mat[i][j] = |a[i-1]-b[j-1]| + min(mat[i-1][j], mat[i][j-1], mat[i-1][j-1])，返回 mat[n][m]。
     **边界必须照抄**：一个序列为空、另一个不空时返回 +inf（不是 NaN 也不是 0）。
     实测 000001@20250310 的第 293、294 位就是 inf
     （dtw_ab_on_exchtime_float_price_全天 和 dtw_ab_dis_..._全天）。
     顺带提醒：verify_series.py 的 compare 对「旧 inf、新 inf」也会判成不一致
     （rel = |inf-inf|/inf = NaN，`not (NaN <= rtol)` 为真）。所以这个系列就算完全复刻正确，
     只要验证用的那几个股票日里出现 inf，verify 也会报「不通过」。接手的人要么换验证样本，
     要么先跟 lead 说清这是工具的限制。
  3) numpy 不稳定排序的并列顺序（最麻烦的一块）
     旧代码 `tradesort = trade0.sort_values('price')`，然后取
     `tradesort.exchtime.iloc[0]` 与 `iloc[-1]` 当作「高低价之间」窗口的两端。
     单键 sort_values 走 pandas nargsort → np.argsort(kind="quicksort")，
     在本机 numpy 2.3.5 + AVX512 上落到 x86-simd-sort，**不是稳定排序**。
     实测四组样本的最低价/最高价都有并列：
       000001@20250303 最低价 11.45 并列 251 个、最高价 11.56 并列 302 个
       600519@20250304 并列 4 / 2
       000002@20180601 并列 3 / 16
       300750@20231020 并列 13 / 1
     并列里到底哪一行排在最前/最后，直接决定 res2 那 312 个值的窗口，
     所以**必须逐行复刻 numpy 的 argsort**，不能换成稳定排序。
     好消息：src/okay_database/hm039.rs 已经把 numpy 的 x86-simd-sort argsort 逐行复刻过一遍
     （int64 版，见该文件 410~960 行，注释里写了依据的是 numpy/_core/src/npysort/x86-simd-sort
     下的哪几个文件，并声称与 numpy 2.3.5 结果完全一致）。
     float64 与 int64 都是 64 位、512 位向量下同为 8 lane，算法结构一样，只需要把类型和
     比较换成 f64；而且这里排的 price 列**没有 NaN**，float 版里最难处理的那条 NaN 分支用不上。
     建议：把 hm039 的那段抄过来改成 f64 版，先在 Python 里和 np.argsort(price) 对几个股票日，
     对上了再往下做。
