run_factor_pipeline_regime

描述

方案 2 顺序流水线：run_factor_pipeline_regime（状态进计算过程）。

与 run_factor_pipeline_cross_section（per-date 独立并行）的本质区别： - 严格按日期顺序执行：每个日期先读自己的标量表存储 [t−W, t−1]， 聚类判定当日市场状态 → 状态化参数计算当天因子 → 写 colblk + 写当日标量（为 t+1 备料）。 - 预热期（窗口不足 W 天）：只计算并存储标量，不输出因子（用户定案：前 59 天不算因子）。 - 不能跨日期并行（顺序依赖），速度优化靠：单遍读内存复用 + 预读流水线 + rayon 日内并行。

函数签名

run_factor_pipeline_regime(pipeline, tasks, n_jobs, expected_result_length, trading_days, state_store_dir, window, store_dir, store_factor_names) -> None

参数

pipeline (目前支持 "peaks_regime")
tasks (纯日期列表 [date, ...]（升序，顺序执行）)
n_jobs (rayon 日内并行度 + 投影线程数)
expected_result_length (每股因子数（= N_FACTORS）)
trading_days (交易日历（窗口取最近 W 个交易日）)
state_store_dir (标量表存储目录（每日一个 {date}.bin，14×f64）)
window (滚动窗口 W（默认 59，即 [t−59, t−1]）)
store_factor_names (colblk 列式存储（同 cross_section）)

断点续算：已完成日期写入 _completed_dates；重跑时跳过。
